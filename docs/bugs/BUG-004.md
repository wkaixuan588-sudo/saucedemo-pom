# BUG-004 登录后首屏加载异常缓慢（性能缺陷，量化数据）

| 项目 | 内容 |
|---|---|
| 缺陷编号 | BUG-004 |
| 所属模块 | 登录 → 商品列表首屏（性能） |
| 严重程度 | 一般（Major，性能类） |
| 优先级 | P2 |
| 状态 | Open |
| 发现方式 | 自动化探测脚本（`scripts/find_defects.py`，计时对照实验） |
| 影响账号 | performance_glitch_user |

## 环境与前置条件

- 浏览器：Chromium 1243（无头），网络：本地宽带
- 计时口径：点击 Login 按钮 → URL 变为 inventory.html 且首个商品名渲染完成

## 复现步骤

1. 以 standard_user 登录，记录耗时（重复 2 次取稳定值作对照组）；
2. 以 performance_glitch_user 登录，记录同样口径的耗时；
3. 对比两组数据。

## 实际结果（自动化实测）

| 账号 | 登录→首屏耗时 | 相对倍数 |
|---|---|---|
| standard_user（对照 ×2） | **0.07s** / 0.07s | 1× |
| performance_glitch_user | **5.11s** | **≈73×** |

## 预期结果

同业务操作不同账号的首屏耗时应在同一量级（如 <1s 或差异 <3 倍）。

## 风险与建议

- 5 秒的首屏等待远超用户耐心阈值（业界常见 3s 流失曲线），登录转化会受直接影响；
- 排查方向：该账号会话下服务端/前端是否注入了人为延迟（演示站为故意行为，
  生产环境应定位到具体接口或前端任务）；
- 测试策略建议：关键路径加**性能基线断言**（如 P95 < 阈值），
  用计时对照法（同口径、同环境、多次取值）而非单次绝对值，避免网络抖动误报。

## 证据

- 自动化数据采集：`scripts/find_defects.py` 输出 `BUG-004_performance_glitch_login`
- 本地可复现：`.venv/bin/python scripts/find_defects.py`
