# BUG-002 全部商品图片被替换为同一张 404 占位图（图文不符）

| 项目 | 内容 |
|---|---|
| 缺陷编号 | BUG-002 |
| 所属模块 | 库存页商品图片展示 |
| 严重程度 | **严重（Major）** |
| 优先级 | P1 |
| 状态 | Open |
| 发现方式 | 自动化探测脚本（`scripts/find_defects.py`，图片 src 比对） |
| 影响账号 | problem_user |

## 环境与前置条件

- 浏览器：Chromium 1243 / 视口 1280×800
- 账号：problem_user / secret_sauce

## 复现步骤

1. 以 problem_user 登录进入商品列表页；
2. 观察 6 件商品的图片内容（或检查 `<img>` 的 src）。

## 预期结果

每件商品显示与其名称对应的产品图，6 张图片 src 各不相同。

## 实际结果（自动化实测）

```
standard_user  src（各不相同）:  sauce-backpack-…jpg / bike-light-…jpg / bolt-shirt-…jpg / …
problem_user   src（全部相同）:  sl-404-Cq1a9k9X.jpg × 6
```

- 6/6 张商品图全部指向同一占位图 `sl-404-Cq1a9k9X.jpg`（一张"狗叼网球"照片）；
- 页面显示为：**所有商品都在展示同一张与商品无关的图**。

## 检测方法说明（值得注意的坑）

占位图本身可正常加载（`naturalWidth > 0`），**用"图片是否加载失败"的常规断言检测不到本缺陷**；
正确做法是比对图片 src 的唯一性/与商品目录的映射关系。这也说明 UI 自动化里
"元素存在"和"内容正确"是两回事。

## 证据

- 整页截图：`docs/bugs/evidence/bug-002-problem-user-inventory.png`
- 自动化数据采集：`scripts/find_defects.py` 输出 `BUG-002_problem_user_images`
  （`distinct_srcs: 1, all_same_placeholder: true`）

## 风险与建议

- 用户无法通过图片识别商品，购买决策信息缺失；
- 建议：图片 URL 配置回归校验（src 唯一性 + 与商品映射）；上线路由检查占位图文件名（`sl-404-*`）。
